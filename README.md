# YaM — Яндекс Музыка для Volumio

YaM — плагин музыкального сервиса для [Volumio](https://volumio.com/), который подключает каталог Яндекс Музыки к музыкальному проигрывателю. Он поддерживает поиск, прослушивание альбомов и плейлистов, радиостанции и воспроизведение через MPD. В режиме высокого качества YaM использует локальный прокси на свободном порту, поэтому может работать одновременно с оригинальным плагином.

Для работы нужна подписка Яндекс Музыки и устройство с установленным Volumio. YaM имеет отдельный идентификатор `yam`, поэтому его можно использовать одновременно с оригинальным плагином `yandex_music`.

YaM — форк плагина [Yandex Music для Volumio](https://github.com/achechulin/volumio-plugins-sources/tree/master/yandex_music). Спасибо автору оригинального плагина за проделанную работу и основу проекта.

## Установка из GitHub

1. Включите SSH в настройках Volumio и подключитесь к устройству.
2. Выполните команды:

```sh
cd /home/volumio
git clone https://github.com/GorINIch73/YaM.git
cd YaM
volumio plugin install
```

3. Дождитесь сообщения об успешной установке. Если Volumio предложит включить плагин, подтвердите.
4. В веб-интерфейсе Volumio откройте **Plugins → Installed plugins** и включите **YaM**.
5. Откройте настройки YaM и войдите в аккаунт Яндекс Музыки по логину и паролю либо укажите OAuth-токен.

Команда установки запускается из каталога клонированного репозитория. Volumio установит зависимости из `package.json`.

## Обновление

Подключитесь по SSH и выполните:

```sh
cd /home/volumio/YaM
git pull
volumio plugin update
sudo systemctl restart volumio
```

## Логи и диагностика

1. **В веб-интерфейсе Volumio**: **Plugins → Installed plugins → YaM → настройки → Диагностика → Журнал YaM** — последние 100 строк журнала.
2. **Файл на устройстве** (по SSH, пользователь `volumio`): плагин установлен в `/data/plugins/music_service/yam`, журнал пишется в `yam-diagnostic.log`:

```sh
tail -f /data/plugins/music_service/yam/yam-diagnostic.log
grep 'YaM diagnostics' /data/plugins/music_service/yam/yam-diagnostic.log
```

Файл появляется после первой записи и обрезается, когда превышает 200 КБ.

3. **Общий лог Volumio**, куда попадают сообщения плагина:

```sh
sudo journalctl -u volumio -f
sudo journalctl -u volumio --since "10 min ago" | grep YaM
```

В журнале видны запросы к Яндекс Музыке, снимок очереди MPD, добавление треков в очередь, `prefetch`, `pushState`, `next`/`previous` — этого достаточно, чтобы разобраться с плейлистами и лайками.

## Качество звука

В настройках плагина есть параметр **High quality** (`hq`). По умолчанию он включён, и плагин запрашивает у Яндекс Музыки `quality=lossless` с кодеками `flac, mp3` — так же, как официальный десктопный клиент.

Какой кодек реально вернулся, видно в журнале:

```
clearAddPlayTrack {"track":"34149522:4192590@user:onyourwave","codec":"mp3","bitrate":192,"quality":"nq","ext":".mp3"}
```

Проверка на живом аккаунте (более 150 треков: «Мне нравится», «Тоть», радио, поиск по Radiohead, Queen, Rammstein, Daft Punk) показала, что Яндекс Музыка для этих треков возвращает `mp3 192` даже при запросе lossless. То есть FLAC не «теряется» в плагине — его нет в выдаче сервера для этих треков. Радио («Моя волна») всегда отдаёт MP3 192 — это ограничение самого сервиса.

Бейдж формата в интерфейсе Volumio берётся из фактического кодека ответа, поэтому он показывает реальное качество, а не желаемое.

## Что изменено

- **`next`/`previous`** работают через очередь ядра Volumio, а не только через MPD: «назад» — `stateMachine.play(pos - 1)`, «вперёд» — MPD, если следующий трек уже prefetch'ен (gapless сохранён), иначе — следующий элемент очереди. Раньше «назад» играл текущий трек, потому что в плейлисте MPD был только он.
- **Высокое качество включено по умолчанию** (`hq: true` в `config.json`).
- **Диагностика**: журнал пишется в `yam-diagnostic.log`, добавлены снимки плейлиста MPD и запись фактического кодека/битрейта/качества при добавлении трека.
- **Исправлен разбор `playlistinfo`** (MPD может вернуть объект вместо массива) и `self` в `previous()`.
